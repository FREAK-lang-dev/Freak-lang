# FREAK 0.15.0

Release date: 12 October 2026. This is the shipping V3 release; the V4 compiler remains a development preview.

**V3 now builds V4.** One command takes the V4 compiler's source and produces a working native V4 preview, with no Python anywhere in the route. This release also brings the loops people asked for, real packages, a project test runner, an HTTP floor, and a compiler that refuses wrong programs instead of building them.

Upgrading from 0.14.2? Read [Breaking changes](#breaking-changes) first. Most programs keep building; the ones that stop were usually doing something they shouldn't.

## Highlights

### Build V4 from V3

```sh
freak bootstrap-v4 --source=/path/to/src/compiler/v4 --output=/path/to/new-preview
/path/to/new-preview/freak-v4 build program.fk --output=/path/to/program
```

`freak bootstrap --v4` is an alias. The command compiles the V4 engine and launcher, tests them, and publishes the preview directory only if every check passes. Your installed `freak` is not replaced.

Add `--locked` to build the exact V4 revision this release was verified against (`b43127c4`). The source directory must then hold that revision's files, which the command checks byte for byte against `bootstrap.lock`; the V4 sources in this release's own tree have moved on since and are built without `--locked`. See `docs/v4-locked-bootstrap.md`.

The preview is V4 as it is today: a development compiler with V4's current language limits, not a replacement for V3. An earlier Linux differential check of the locked revision compared 480 inputs against a freshly Python-built compiler of that same revision, with identical output and status. Those are historical, revision-specific results, not a fresh 480-input result for this release.

### Loops

```freak
for each i in 0..10 { }            -- 0 to 9
for each i in 0..=10 { }           -- 0 to 10
for each i in 0..10 step 2 { }     -- 0, 2, 4, 6, 8
repeat 10 times with i { }         -- i counts 0 to 9
for (pilot i = 0; i < 10; i += 1) { }

while n < 3 { n += 1 }
repeat while n < 6 { n += 1 }
```

Pick whichever reads best to you; they mean what they look like.

### Bindings

- `grounded pilot x = 1` is the same as `fixed pilot x = 1`. A grounded pilot isn't going anywhere.
- An ordinary `pilot` can be reassigned. `pilot mut` still works and means the same thing.
- Fields accessed through a `fixed` or `grounded` binding cannot be reassigned.

### Smaller language additions

- Statements on one line can be separated with `;`.
- Words can be ordered with `<`, `>`, `<=` and `>=`, byte by byte. Uppercase sorts before lowercase, and the comparison is not locale-aware.
- `fs::read_checked(path)` with `check result` tells a missing file apart from an empty one. The result must be held in a local inside a task:

  ```freak
  task main() {
      pilot r = fs::read_checked("config.txt")
      check result r {
          ok(text) -> { say text }
          err(e) -> { say "could not read: " + e }
      }
  }
  ```

### Projects, packages and tests

- `freak init NAME --template=cli|lib|http` creates a project with a manifest, sources and a test.
- `freak test` runs a project's tests with the installed compiler.
- Libraries declare modules and exports in `hangar.toml`; applications import them with `use name::{item}`. Build, run and test consume declared path and locked Git dependencies, including offline builds from an admitted lock. Legacy Hangar installation has the narrower path-dependency and lock-format limits listed below.
- `freak build -o NAME` (or `--output=NAME`) chooses the output file.
- `freak run program.fk -- args` passes arguments through to the program.
- `freak doctor` checks for a supported Clang (major version 15 or later).

### HTTP floor

A synchronous HTTP/1.1 server layer for one request per connection, with bounded request sizes, deadlines and a loopback default, built on the vendored llhttp parser. `freak init app --template=http` shows it in use. This is the transport layer; routing and frameworks are left to packages.

### Faster checked arithmetic

Integer overflow and division by zero are now checked on both backends. The arithmetic checks are emitted inline, avoiding a helper call for each checked operation. Performance depends on the program and toolchain; no universal comparison with 0.14.2 is implied.

## Breaking changes

Each item below builds or runs on 0.14.2 and behaves differently on 0.15.0.

**Programs that now stop at run time**

- **Integer overflow** stops the program with `integer overflow in addition` (and similar for `-` and `*`). 0.14.2 wrapped around silently.
- **Division or remainder by zero** stops the program. 0.14.2 crashed or produced a meaningless value.
- **A word index out of range** stops with `word index out of range` on both backends. On the LLVM backend 0.14.2 returned whatever was in memory.

**Programs that no longer build**

- **An integer literal too large for 64 bits**, such as `99999999999999999999`.
- **A stray value as a statement**, such as `say 1 2` or `say "a" "b"`. 0.14.2 printed the first value and dropped the second.
- **Executable top-level statements in a file that has `task main()`.** 0.14.2 skipped them silently. Move them into `main`. A script with no `main` still runs its top-level statements in order.
- **A file with nothing to run**: empty, only comments, or only declarations without `main`.
- **A `when` arm that can never run**: a repeated literal, or any arm after `_`.
- **Expression-like interpolation outside a name or field path.** `"{n}"` and `"{p.x}"` work; `"{n + 1}"` and an unclosed path such as `"{n"` are errors. Empty, nested/non-expression and colon-containing object-like brace text retain their literal meaning. Write `\{` and `\}` for literal braces, including expression-like text. The colon exemption and its qualified-call consequence are listed below.
- **An unknown escape** such as `"\q"`. 0.14.2 dropped the backslash.
- **Changing a field of a `fixed` (or `grounded`) shape.**
- **A `use` that names nothing.** 0.14.2 accepted `use nonexistent::thing`.
- **Calling a task whose name a local variable also uses.** `pilot f = 3` followed by `f()` now reports `local value shadows this name`. Rename one of them.
- **`while` as a name.** It is now a keyword.

**Programs whose meaning changes**

- **Capitalised truth literals.** `TRUE`, `Yes` and other capitalised spellings now mean true. 0.14.2 read them as false.
- **`give` at the end of one line and `back` at the start of the next** are no longer joined into `give back`. `give` and `back` on their own are ordinary names again.

**Tools**

- `hangar add` of a package that doesn't exist now exits with an error. 0.14.2 reported success.

## Fixes

- Script-style programs (top-level statements, no `main`) build and run.
- The LLVM backend's word indexing returns characters, matching the C backend.
- `pilot give = 1` and `pilot back = 2` are valid again.
- Error messages name the user's file and the user's identifiers.
- `--strict-borrow` no longer demands `pilot mut` for reassignment.
- A lexical source-admission error in `freak build`, such as an unterminated word, now includes the ordinary `BUILD FAILED` footer while retaining exit status 1, the original diagnostic, file location and caret, and stale-output cleanup.

## Known issues and limits

- **Diagnostic voices are not switched on.** The prepared voice selector is outside the shipping CLI assembly, so no voice lines appear. Integration is tracked in [#169](https://github.com/FREAK-lang-dev/Freak-lang/issues/169).
- **The library template's example consumer cannot use legacy `hangar install` for its local path dependency.** Legacy installation can ask for a Git source instead. Build, run and test consume the declared path graph. Installation support is tracked in [#170](https://github.com/FREAK-lang-dev/Freak-lang/issues/170).
- **Interpolation remains path-only, with a literal-brace compatibility rule.** `{}`, `{{n}}` and object/JSON-like text are literal. The colon-containing-body exemption also prints `"{process::args_count()}"` literally. Explicitly distinguishing qualified calls is tracked in [#171](https://github.com/FREAK-lang-dev/Freak-lang/issues/171); this release preserves the current language contract.
- **`check result` requires a local inside a task.** Top-level script aliases, annotations and global result storage are unsupported.
- **Existing writable project directories can be refused by `hangar init`.** Group-writable POSIX parents and inherited Windows ACLs may fail the protected-parent requirement. Create-only support is tracked in [#164](https://github.com/FREAK-lang-dev/Freak-lang/issues/164).
- **Legacy Hangar writers still reopen the project pathname.** Cooperative locking does not prevent an external directory replacement from redirecting their later effects. Carrying the held identity through those effects is tracked in [#165](https://github.com/FREAK-lang-dev/Freak-lang/issues/165). Legacy mutating commands also refuse retained journals and graph-v2 locks; they do not provide the declared-graph installation/update path.
- **Printed init commands need shell quoting.** Spaces or literal POSIX backslashes can make the suggested `cd` command incorrect. Quote the path yourself; tracked in [#166](https://github.com/FREAK-lang-dev/Freak-lang/issues/166).
- **Init can report an outdated output pathname after its parent is renamed.** Publication remains in the held original directory, but the printed path may no longer name it. Truthful location reporting is tracked in [#168](https://github.com/FREAK-lang-dev/Freak-lang/issues/168).

### Development V4 and test tooling

The preview retains V4's current language and backend limits. Inline map-literal indexing and aggregate LLVM lowering are not promised by this release. It is not a replacement for shipping V3.

- Grouped multiline member separators can miss the reserved lowercase `while` diagnostic ([#167](https://github.com/FREAK-lang-dev/Freak-lang/issues/167)).
- Alias-route MIR snapshots can fail validation for an otherwise positive development input ([#163](https://github.com/FREAK-lang-dev/Freak-lang/issues/163)).
- Numeric-counted emission scaling work remains deferred ([#161](https://github.com/FREAK-lang-dev/Freak-lang/issues/161)). That issue's measurement belongs to an unintegrated development branch, not a demonstrated shipping V3 or locked-preview failure.
- Opt-in native Clang identity witnesses do not support every toolchain-manager dispatcher ([#160](https://github.com/FREAK-lang-dev/Freak-lang/issues/160)); this is a test-provider limitation, not a demonstrated failure of ordinary compilation.
- Optional historical V4 benchmark baselines still need stronger compiler-provenance binding ([#148](https://github.com/FREAK-lang-dev/Freak-lang/issues/148)). Historical performance comparisons are host-, revision- and workload-specific.

Other open historical snapshot reports require reconciliation against their current repairs; their issue state alone is not evidence that the old failure still occurs.

## Platforms and verification

Release archives target Linux x64, Linux arm64, macOS arm64 and Windows x64. PR CI covers Linux x64, macOS arm64 and Windows x64, including the locked V4 bootstrap. Tagged release CI separately builds and tests the exact extracted archives before publishing them; passing an earlier PR is not a substitute for that archive verification.

A supported Clang (major version 15 or later), linker and platform SDK are required. Windows uses the LLVM-MinGW UCRT/GNU toolchain and the documented local-filesystem/provider boundaries; see [the installation guide](https://github.com/FREAK-lang-dev/Freak-lang/blob/v0.15.0/README.md) and [locked bootstrap guide](https://github.com/FREAK-lang-dev/Freak-lang/blob/v0.15.0/docs/v4-locked-bootstrap.md). Android/Termux validation remains open ([#114](https://github.com/FREAK-lang-dev/Freak-lang/issues/114)).
