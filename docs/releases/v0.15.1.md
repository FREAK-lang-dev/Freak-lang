# FREAK 0.15.1

Release date: to be set when the tag is cut. A patch release on top of 0.15.0 "Maverick". Nothing that built on 0.15.0 stops building; the one behavior change is the caret fix under [Fixes](#fixes).

**Hangar talks to the registry now.** You can depend on a package by version, log in, and publish your own, all from the `hangar` command.

## Highlights

### Registry packages in Hangar

```toml
[dependencies]
cockpit = "^0.1.0"
```

```sh
hangar install                 # resolves cockpit from the registry and pins it
hangar auth login              # device login: approve the code in your browser
hangar publish --dry-run       # shows what would be uploaded
hangar publish
```

- Registry dependencies resolve against the Ordnance registry, are pinned in `hangar.lock` (lock v2) by archive SHA-256, and are cached so later builds work offline.
- `hangar auth login`, `hangar auth status` and `hangar auth logout` use a device flow. Credentials live in your user config directory with owner-only permissions. `hangar login` and `hangar logout` are shortcuts.
- `hangar publish` packs exactly the inputs your manifest declares and uploads them.
- `add`, `install`, `update`, `remove`, `version`, `audit` and `outdated` all understand lock v2 projects. `outdated` compares your registry pins with the newest published version.
- Packages with dashes in their names are imported with underscores: `cockpit-extras` becomes `use cockpit_extras::{...}`.
- Lock pins for local packages are stored relative to the project root, so a moved or cloned project keeps working, including with `--locked`.
- The registry defaults to `https://hangar.freaklang.dev/api/v1`. Set `HANGAR_REGISTRY` to use another one.

### Faster repeated builds

`freak build` and `freak run` keep verified runtime objects in a private per-user cache and reuse them on later builds. Your own code is still compiled and linked fresh every time, and the cache is shared by every project on your machine. A cache entry is used only when the compiler, runtime sources, target, optimization level and LTO setting all match; anything unsafe, busy or unproven falls back to a normal source build.

### Shorter build flags

- `--O0` through `--O3` set the optimization level (the default is `--O2`).
- `--flto` turns on full LTO and `--tlto` turns on thin LTO.
- The older `--opt=N` style flags still work.

### Diagnostic cast (opt-in)

`build`, `run`, `check` and `transpile` accept `--diagnostic-cast=off|minimal|normal`. When it's on, the cast comments on your errors after the normal diagnostic. The diagnostic itself and the exit status are unchanged. The default is `off`; full character voices are V4 work.

### HTTP fixes

- `HEAD` responses never carry a body, including on rejections.
- `205 Reset Content` responses always use zero-length framing.
- After rejecting a request, the server drains a bounded amount of the client's remaining input before closing, so slow clients get the response instead of a reset.

### IRBuilder experiment

The repository now contains an opt-in prototype backend that lowers V3's checked AST through LLVM's real IRBuilder (LLVM 19 C API) instead of writing textual IR. It covers int-only programs for now: tasks, arithmetic, comparisons, `if`/`else` and `say`. It is not part of the shipped `freak` binary, and the default backend has not changed. See `docs/v35-llvm-builder-experiment.md`.

### V4 preview

Building the V4 preview from V3 works the same as in 0.15.0:

```sh
freak bootstrap-v4 --source=/path/to/src/compiler/v4 --output=/path/to/new-preview
/path/to/new-preview/freak-v4 build program.fk --output=/path/to/program
```

The preview is still a development compiler, not a replacement for V3.

## Fixes

- **Caret ranges on 0.x versions** now follow Cargo and npm: `^0.1.0` means `>=0.1.0, <0.2.0` and `^0.0.3` means exactly `0.0.3`. Before, `^0.1.0` could resolve to `0.3.0`. If you relied on the wider match, widen your constraint.
- `hangar init` writes `kind = "app"` and `entry = "src/main.fk"`, so `hangar add` works in a fresh project instead of refusing the manifest.
- `hangar add` writes path, git and version values through the TOML writer, so Windows paths like `..\lib1` no longer break `hangar.toml`.
- `hangar init --help` and `freak init --help` print usage instead of creating a project called `--help`.
- Registry errors name the HTTP status next to the server's message.
- `hangar auth logout` only says the session was revoked when the registry confirms it. Your local credentials are removed either way.
- When `freak run` stops before building because an import, the package graph or `--locked` was rejected, it says so. It used to blame a missing hashing tool.
- The options box in `freak help` keeps the diagnostic-cast and legacy flag lines inside its border.
- The lexer no longer prints a stray `Source length` debug line.

## Upgrading

Install the same way as 0.15.0: the release binaries, `install.sh`, `install.ps1`, Homebrew, Scoop or WinGet. Your projects, locks and caches from 0.15.0 carry over. If you have a `^0.x` constraint that should accept newer minor versions, change it to `>=0.x.y` before running `hangar update`.
