# A2 type-text inventory

Architecture lane A2 ("no type text past TY"), first row: size the work.
Types still cross every boundary after TY as `word` spellings. This file
counts those reads in the four crates past TY and groups each read by the
question the code asks of the spelling. It is the baseline the A2 rows
shrink; regenerate it with

```
python src/compiler/v4/tools/type_text_inventory.py > /tmp/inventory.md
```

and paste the tables below when a row lands. Classification is per line and
first-match (see `QUESTIONS` in the tool), so a single site can be
misfiled; totals are exact call-site counts.

## What the numbers say

- The checklist's earlier figure (108 MIR type reads in Meiya and codegen,
  162 after PR #143) has more than doubled with tier 3: Meiya and codegen now
  read MIR type spellings at 328 sites, and `v4_mir_rvalue_ty` alone at 214
  of them. Native aggregates, sums, closures, lend ABI and dyn all key off
  the spelling.
- Codegen asks three kinds of question. It selects LLVM types and layouts
  (47 direct MIR reads, plus most of the 75 bindings feed the same helpers),
  it decomposes types (lend target, raw-pointer target, fixed-array element,
  sum case, 113 sites across both families) and it compares spellings to
  literals. Of the literal compares, most are against LLVM spellings
  (`double`, `i64`, `i8`, `i32`, `void`) chosen from FREAK spellings earlier
  in the same task, and 30 are emptiness tests (`ty == ""`, type unknown).
  Only a handful compare FREAK spellings directly (`float`, `int`, `uint`,
  `lend word`).
- Meiya's reads are mostly predicates: is Copy, is lend, may store a lend,
  payload holds a word (26 direct, 46 bound first). These map one to one
  onto the typed questions in the A2 row "Meiya asks typed questions".
- `v4_ty_canonical_type` (82 reads past TY) and `v4_ty_lend_target_type`
  (48) are the hottest TY helpers. Both disappear once a `TypeId` is
  canonical by construction and lend types are a constructor, not a prefix.
- MIR Build still has the six `v4_ty_type_text` call sites the checklist
  names. The other type-text helpers past TY (function return text 10,
  fixed-array length text 7, const integer text 2, integer literal text 1,
  signature display 2) total 22 sites: 11 in MIR Build, 2 in Meiya and 9 in
  codegen. That is the A2 row "remaining type-text helpers past TY" (the
  checklist said about 25).

## Suggested order for the A2 rows

1. `TypeId` table owned by TY, with snapshot and restore, interning the
   canonical spelling, so every existing accessor can return an id beside
   its word without changing callers.
2. Typed predicates first (Meiya's list above, plus codegen's 20 predicate
   sites): they need only an id and replace whole helper families.
3. Decomposition accessors by id (lend target, pointer target, element,
   slot, case, generic argument).
4. LLVM type selection from `TypeId` in one codegen helper; the LLVM-spelling
   literal compares go with it.
5. MIR stores `TypeId` for locals, places and rvalues last, when no reader
   left needs the word. That is the L row and the one that touches the MIR
   snapshot format.

Steps 4 and 5 rewrite codegen paths tier 3 is still extending (Map/Set,
owned dyn, Shared, raw alloc); they wait for those lanes to settle.
